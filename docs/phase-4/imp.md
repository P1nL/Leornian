## 3. 工作包实施细节

### WP01：材料、绑定、期限与兼容

改动位置：`modules/knowledge/{contracts,application}.py`、`modules/learning` 的新绑定合同/用例、`bootstrap/knowledge.py`、`platform`、新增迁移、相应 API/生成类型。

1. 建立 spec S03 的文档/块、材料需求、选材和绑定身份；先落地实际用到的记录，不一口气建所有未来空表。
2. 拆分变化检查、学习适用性复核、真实用途许可、保留策略；实现可配置长周期默认，不以日期单独判定教材失效。
3. 新消费者使用精确 binding，不把 source 当前 head/corpus active 指针当已学习内容；旧 SourceRef/旧 Run 保持旧解释。
4. 设计旧七天确认记录到新模型的可追溯兼容映射，不批量改旧回执或凭空延长真实许可。
5. 在调用链准备好后替换 `SourcesPanel.tsx` 的“确认使用七天”常规流程；不得先移除检查而没有新权限/绑定实现。

退出：跨复核日期仍能恢复固定版本；撤权/作用域错误仍拒绝；旧接口/Run 不获得新语义或工具。

### WP02：用户模型配置、自动接入与专用协议

改动位置：`platform` 用户模型配置/凭据解析及受控存储、`agent_runtime` 调用装配、`modules/knowledge` 材料任务/解析，API/Worker/relay，桌面模型设置及必要安全存储桥接。

1. 先实现用户模型设置：提供方连接、独立密文凭据/安全存储、非秘密 Profile 及职责映射，覆盖全部模型通道。支持保存、主动测试、轮换、撤销/删除和生效范围，不在客户端明文持久化 key。
2. 接入当前用户凭据解析、base URL/协议/区域/能力检查，冻结非秘密配置与 credential reference/version。缺配置明确等待，不隐式回落到开发共享 key；轮换/撤销不得重发或改写已发送请求。
3. 建立受控获取/上传引用、原文存储与 HTML/Markdown/PDF 解析；扫描或差区域按页/区域 OCR，原文不可被“纠错”覆盖。
4. 为 OCR/Embedding/Rerank 建真实协议 Profile，保存实际模型/区域和回执；不将专用 API 伪装成有思考/工具链的聊天请求。
5. 确定每类问题的自动策略：版面/区域重识别、正文提取切换、表格处理、代码疑点复核、换已授权材料等。
6. 状态/进度/取消根和后继持久化；恢复从已提交阶段承接，前台让位；未知请求不重发。
7. 按已明确的千问授权用真实材料比较候选与对照，记录实际质量、延迟、用量和费用；只在账号/通道确实不可用时等待，不将已经获得的费用或地域许可继续列为阻断。

退出：用户自配连接能驱动各模型职责，密钥/私有材料跨用户隔离、撤销和公开数据边界成立；正常材料路径及已知失败自动推进，无学习者审核/重试/发布按钮。协议夹具只证明合同，不证明模型可用或材料质量。

### WP03：检索、覆盖与教学实际消费

改动位置：`modules/knowledge` 的检索/覆盖 Facade 与存储，`bootstrap/teaching_context.py`、`modules/learning/{planning,lessons}.py`、供题/审核装配、来源阅读组件及 API。

1. 配置全文索引与实际向量索引；同模型/维度/预处理空间内读写，私有和共享范围先过滤。
2. 实现词法/语义召回、融合、排序、上下文扩展，保存精确选择与缺口；大请求分批完整处理。
3. 材料缺口回 WP02，不降低核心目标；盲解、作者和审核使用其职责所需的不同可见材料。
4. 将规划、课时、日常 Tutor、题包与审核接入新 binding；接受结果时复核当前用途，不给所有角色自动开放工具。
5. 做实际引用定位到文档版本/块，右侧来源阅读不另建学习工作区。

退出：真实消费者接受可追溯材料；中文/英文/代码问题的覆盖和缺口均可观察，不以索引写入或相似度单独验收。

### WP04：增量续检、通知和用户迁移

改动位置：`knowledge` 检查/变更/更新提案，`learning` 用户决定/迁移，`delivery` 通知读模型，`bootstrap` 具名协调器，通知中心/来源页。

1. 条件请求与原文比较分开；识别非教学噪声，保留新原文，逐块比较并建立真实依赖。
2. 字面改写做定向等价检查；事实/代码/版本变更做影响分析。以用户当前绑定为基线检查累计变化。
3. 未变块复用处理/向量/审核，变更块只处理必要步骤；模型更换仅重建其索引，不重新生题。
4. 新版自动准备，通知说明差异/影响/迁移代价并去重。默认继续旧版，不用通知已读/关闭触发迁移。
5. 用户接受/稍后/本轮保留旧版采用版本与幂等合同；接受时创建明确 successor，不覆盖历史。若路线本身变化，不能省略必要确认。

退出：页脚时间戳不触发全链路，等价改写不全书重审，实质变化只影响实际依赖；保留旧版和并发接受均正确。真实授权/安全故障不被“留用”绕过。

### WP05：交互工件、候选与动作

改动位置：`modules/tutor` 的独立 Learning Artifact 合同/存储，`bootstrap` 教学/动作协调，原 `assessment/execution/learning/item_bank` 公开接口，`delivery` 和 API。

1. 新增闭合交互 DTO 与 timeline item，不把 0022 文档表原地变成可执行工件。
2. 根据当前教学/材料/发布/运行资格构建精确候选；新角色冻结工具版本，旧 Run 不升级。
3. 实现消息/工件/教学 CAS/Turn 终态/事件一致提交，防止有文字无工件或有按钮无权限。
4. 动作检查当前 scope、expected revision 和幂等键；只委派原 owner，GET 不执行或评分。
5. 普通练习运行通过即完成；Gate 整组锁定和独立性保留。结果可先可靠保存，讲评失败不丢评分。

退出：非法候选和原子提交失败无半交付；重复动作/双入口无重复业务执行；取消/迟到/未知维护既有保证。

### WP06：对话内界面与重连恢复

改动位置：`TutorPanel.tsx`、对话条目/工件 renderer、`App.tsx`、客户端 API/SSE/历史、生成合同和必要样式。

1. 先复用现有知识检查和 Python 练习业务，在对话内完成引入—操作—结果—讲评，而不是把文档列表挪进气泡。
2. renderer 按闭合类型和 server allowed_actions 展示；保留现有界面身份，不以本包重做全站视觉。
3. 草稿、折叠和滚动按用户/会话/工件/内容版本隔离；刷新恢复，不自动运行/提交；正式业务状态来自服务器。
4. 同一 actor 快照/SSE 支撑条目顺序和版本更新，大详情/历史分页，不增加每个工件的第二套事件流。
5. 明确处理中、等待讲评、冲突、已替换、取消与无权限等状态，窄屏可操作、键盘入口可用。

退出：实际浏览器中的两条纵向路径完整；重连不丢工件身份、不重复评分；大详情读取不泄露答案或私有提交。

### WP07：辅助、演示、评审、SQL 和预览

改动位置：原题库内容/发布合同、Assessment 辅助/曝光、对应 renderer、受控 Preview/SQL Profile、源文档抽屉。

1. H1—H3、直接答案、辅助和展示回执共用当前作用域，回看/重放去重；后继沿原完整审核/未见规则。
2. 逐类补全知识检查、代码评审、交互演示、SQL、HTML/CSS 及来源定位，不只增加 renderer 名称或占位卡。
3. 演示事件/可见时钟、受控 Preview 桥接有真实边界；不可信代码不进入主 DOM，不获得宿主 API。
4. SQL 首批 MySQL/PostgreSQL/SQLite 的方言/数据/结果显示与评分分开，Schema 复制不自动插入；预览成功不记正式通过。框架/多文件工件须绑定 WP11 的已验证项目 Profile，不能生成任意执行入口。
5. 只有已验证 scorer/Profile 的类型进入独立证据；新展示仍纳入实际曝光与关系审查。

退出：每一类型有真实可用路径；辅助成功不计无辅助掌握，演示/阅读不生成虚假证据；原生预览若未验收不得标可用。

### WP08：会话模式、答疑和续行仲裁

改动位置：`tutor` 教学会话/分支/意图，原 relay/Runtime 装配，conversation item 和前端控制。

1. 引导/自由阅读、暂停/恢复和主题控制持久化，当前权限与教学版本一致。
2. 工件等待期间的问题建立服务端锚定单层答疑，结束后可折叠但保留完整历史。
3. 续行先持久化，按既定优先级认领；同会话一个可发布前台轮次，用户消息/考试等条件优先。
4. 结果事件重放、后台计时和并发 claimant 不重复推进；作用域更新使旧意图安全失效，不恢复旧授权。

退出：工件等待、答疑、回主线、自由模式与取消竞态可实际验证，无模型自我续行失控。

### WP09：能力证据与 FSRS 复习

改动位置：`learning` 当前 progress/execution evidence、review 合同/用例，Assessment 结果 Facade、复习工件及配置。

1. 明确概念、执行、新情境的证据来源及适用范围，给出可解释投影，不新增 Tutor 写掌握入口。
2. 锁定真实 FSRS 实现/参数版本，保存真实 review log、记忆状态及评分/自评来源，按依赖官方合同接入。
3. 兼容旧三档自评，不虚构新档位或客观评分。冷启动默认参数可追溯，只有真实日志才用于拟合。
4. 到期活动、回答、暂停/恢复和新安排幂等，复习进入对话工件，不把调度视作教学完成。

退出：真实复习活动影响安排但不伪造 Gate；旧记录保持原含义，失败/辅助和不同能力不混算。

### WP10：受控主动教学

改动位置：WP08 教学意图/模式、WP09 到期事件、relay/worker、用户偏好与客户端。

1. 由已提交业务事件和到期事实产生意图，不让定时器直接调用 provider。
2. 检查模式、暂停/时段、当前前台/考试/用户输入及来源绑定；同触发事实消费去重。
3. 无新事实时不自我连续发问；用户可停止后续，不能自动切教材、确认路线、开考或作答。

退出：允许模式下能主动提出正确下一步；自由问答、暂停、前台和考试均有实际优先保证。

### WP11：本机执行、按需环境与课程能力

改动位置：`execution` 公开合同/环境授权/存储、Runner Controller/可信环境配方、桌面首次引导/环境进度及必要本机桥接、`infra` 本地组件管理、Assessment scorer、教材/题库/工件矩阵。只改实际消费者，不增加远程执行分支。

先行里程碑为执行基座，后续里程碑为逐组合课程；分别记录验证层次，不能把单一注册表当作两者都完成。

1. 核对当前 `ExecutionClaim(code, inputs)`、Python 命令、固定资源及 `python_input_ref` 调用链，增加版本化项目/文件/Profile/测试合同，兼容旧任务；只按实际消费者建立字段和适配器。
2. 复用 job、认领/租约、回执、过期/迟到、取消与幂等上报；增加真实编译/运行阶段及相配的资源/心跳/定向清理。模板/命令/镜像由可信 Profile 决定，不由模型自由构造。
3. 建立文件工作区和受控依赖准备：相对路径/容量、锁文件、精确版本、隔离构建及只读可复用环境；编译/安装脚本不在宿主执行，不把密钥或 Docker 控制权限放进学习者环境。
4. 用基础真实样本验证解释执行、编译执行和方言查询的共用通道；Rust/C++ 可先评估标准库编译 Profile，按实际资源测试调整，不把环境适配评估当成已经确认的完整课程范围。
5. SQL 首批分别接 MySQL/PostgreSQL/SQLite，提供与业务库分离的临时数据、最小权限和结果 scorer；SQL Server/Oracle 等明确未完成/扩展状态，不以 SQLite 代测。
6. 受控框架项目按课程模板、锁定依赖和真实测试逐项接入；HTTP/数据库依赖只在本机任务私有测试范围可达。用户明确授权后自动准备环境，不维护镜像；不增加远程/多租户执行模式，不直接开放任意互联网仓库。
7. 建立实际课程矩阵，按 Python、JS/TS、SQL/HTML/CSS、Java/Go/C# 的依赖推进。将教材、课时、工件、盲解真实执行、完整审核、正式练习/Gate、补救与复习接入原 owner，不额外开一套执行或评分引擎。
8. 旧 registry 其他语言单列声明/未完成状态；额外正式承诺依现行产品范围核对，不能自行删减或假通过。
