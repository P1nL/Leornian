## 3. 工作包实施细节

### WP01：材料、绑定、期限与兼容

改动位置：`modules/knowledge/{contracts,application}.py`、`modules/learning` 的新绑定合同/用例、`bootstrap/knowledge.py`、`platform`、新增迁移、相应 API/生成类型。

1. 建立 spec S03 的文档/块、材料需求、选材和绑定身份；先落地实际用到的记录，不一口气建所有未来空表。
2. 拆分变化检查、学习适用性复核、真实用途许可、保留策略；实现可配置长周期默认，不以日期单独判定教材失效。
3. 新消费者使用精确 binding，不把 source 当前 head/corpus active 指针当已学习内容；旧 SourceRef/旧 Run 保持旧解释。
4. 设计旧七天确认记录到新模型的可追溯兼容映射，不批量改旧回执或凭空延长真实许可。
5. 在调用链准备好后替换 `SourcesPanel.tsx` 的“确认使用七天”常规流程；不得先移除检查而没有新权限/绑定实现。

退出：跨复核日期仍能恢复固定版本；撤权/作用域错误仍拒绝；旧接口/Run 不获得新语义或工具。

### WP02：用户模型配置、自动接入与专用协议

改动位置：`platform` 用户模型配置/凭据解析及受控存储、`agent_runtime` 调用装配、`modules/knowledge` 材料任务/解析，API/Worker/relay，桌面模型设置及必要安全存储桥接。

1. 先实现用户模型设置：提供方连接、独立密文凭据/安全存储、非秘密 Profile 及职责映射，覆盖全部模型通道。支持保存、主动测试、轮换、撤销/删除和生效范围，不在客户端明文持久化 key。
2. 接入当前用户凭据解析、base URL/协议/区域/能力检查，冻结非秘密配置与 credential reference/version。缺配置明确等待，不隐式回落到开发共享 key；轮换/撤销不得重发或改写已发送请求。
3. 建立受控获取/上传引用、原文存储与 HTML/Markdown/PDF 解析；扫描或差区域按页/区域 OCR，原文不可被“纠错”覆盖。
4. 为 OCR/Embedding/Rerank 建真实协议 Profile，保存实际模型/区域和回执；不将专用 API 伪装成有思考/工具链的聊天请求。
5. 确定每类问题的自动策略：版面/区域重识别、正文提取切换、表格处理、代码疑点复核、换已授权材料等。
6. 状态/进度/取消根和后继持久化；恢复从已提交阶段承接，前台让位；未知请求不重发。
7. 按已明确的千问授权用真实材料比较候选与对照，记录实际质量、延迟、用量和费用；只在账号/通道确实不可用时等待，不将已经获得的费用或地域许可继续列为阻断。

退出：用户自配连接能驱动各模型职责，密钥/私有材料跨用户隔离、撤销和公开数据边界成立；正常材料路径及已知失败自动推进，无学习者审核/重试/发布按钮。协议夹具只证明合同，不证明模型可用或材料质量。

### WP03：检索、覆盖与教学实际消费

改动位置：`modules/knowledge` 的检索/覆盖 Facade 与存储，`bootstrap/teaching_context.py`、`modules/learning/{planning,lessons}.py`、供题/审核装配、来源阅读组件及 API。

1. 配置全文索引与实际向量索引；同模型/维度/预处理空间内读写，私有和共享范围先过滤。
2. 实现词法/语义召回、融合、排序、上下文扩展，保存精确选择与缺口；大请求分批完整处理。
3. 材料缺口回 WP02，不降低核心目标；盲解、作者和审核使用其职责所需的不同可见材料。
4. 将规划、课时、日常 Tutor、题包与审核接入新 binding；接受结果时复核当前用途，不给所有角色自动开放工具。
5. 做实际引用定位到文档版本/块，右侧来源阅读不另建学习工作区。

退出：真实消费者接受可追溯材料；中文/英文/代码问题的覆盖和缺口均可观察，不以索引写入或相似度单独验收。

### WP04：增量续检、通知和用户迁移

改动位置：`knowledge` 检查/变更/更新提案，`learning` 用户决定/迁移，`delivery` 通知读模型，`bootstrap` 具名协调器，通知中心/来源页。

1. 条件请求与原文比较分开；识别非教学噪声，保留新原文，逐块比较并建立真实依赖。
2. 字面改写做定向等价检查；事实/代码/版本变更做影响分析。以用户当前绑定为基线检查累计变化。
3. 未变块复用处理/向量/审核，变更块只处理必要步骤；模型更换仅重建其索引，不重新生题。
4. 新版自动准备，通知说明差异/影响/迁移代价并去重。默认继续旧版，不用通知已读/关闭触发迁移。
5. 用户接受/稍后/本轮保留旧版采用版本与幂等合同；接受时创建明确 successor，不覆盖历史。若路线本身变化，不能省略必要确认。

退出：页脚时间戳不触发全链路，等价改写不全书重审，实质变化只影响实际依赖；保留旧版和并发接受均正确。真实授权/安全故障不被“留用”绕过。

### WP05：交互工件、候选与动作

改动位置：`modules/tutor` 的独立 Learning Artifact 合同/存储，`bootstrap` 教学/动作协调，原 `assessment/execution/learning/item_bank` 公开接口，`delivery` 和 API。

1. 新增闭合交互 DTO 与 timeline item，不把 0022 文档表原地变成可执行工件。
2. 根据当前教学/材料/发布/运行资格构建精确候选；新角色冻结工具版本，旧 Run 不升级。
3. 实现消息/工件/教学 CAS/Turn 终态/事件一致提交，防止有文字无工件或有按钮无权限。
4. 动作检查当前 scope、expected revision 和幂等键；只委派原 owner，GET 不执行或评分。
5. 普通练习运行通过即完成；Gate 整组锁定和独立性保留。结果可先可靠保存，讲评失败不丢评分。

退出：非法候选和原子提交失败无半交付；重复动作/双入口无重复业务执行；取消/迟到/未知维护既有保证。

### WP06：对话内界面与重连恢复

改动位置：独立固定的 LibreChat 前端来源与实际采用部分、Leornian 身份/HTTP/快照/SSE 适配、`TutorPanel.tsx`、对话条目/工件 renderer、`App.tsx`、生成合同和必要样式。不整体覆盖现有 Desktop。

界面执行基准（2026-11-07）：保留 5180 当前布局、导航、欢迎/输入体验、学习菜单、设置/来源面板和工件视觉；复用 5181 的真实业务适配能力，逐项替换演示数据和动作。基准确认后，按用户“进行接线”在独立 5183 验证核心链，再将 5180 切为真实入口；5181 保留工程联调、5178 保留未迁移功能，独立演示移至 5182。

### 4.4 节点教学：怎样扮演学员

验收普通学员的体验时，只给扮演者学习目的、已有基础、截至本轮学员能看到的内容和自己实际做过的操作。先读 Tutor 交付的原话，再决定要不要开口；不预写整段对话，也不把后续教学安排或验收点交给学员。

- 第一次进来还没有问题，就听开场。能跟上时可以继续听，不发送占位的“继续”。遇到困惑就用自己的话说眼前那一点；Tutor 提问时，可以短答、猜错或说“不知道”。只有实际试过才报告运行结果。
- 例如只看到 `console.log('你好')` 时，初学者可能问“引号也会显示出来吗？”；如果上一句已经讲清引号不会显示，就不再照样例问。学员也可以有自己的联想，但不用每轮都安排一次反驳。
- 验收人员另记 Tutor 有没有回应困惑、什么时候接回节点目标、接下来由谁引导。如果 Tutor 反复出题或停在原地，就记录实际经过，不让学员发“别再考我、接回主线、把这节收尾”来补救。遇到真实的练习邀请后说“这题先跳过吧”，单列为**明确偏好**样本，用来检查 Tutor 是否尊重选择。
- 验证动手环节时，学员可以说自己想改什么，不点名编辑器、组件或终端。验收人员分别核对这轮是否交付了对应控件、草稿是否可改、是否有真实运行入口和回执；“题目准备中”不记为已经能运行。仅在解释程序输出时提及“终端”，与要求学员离开应用去执行，是两种不同结果。
- 一次编辑器试跑用同一份草稿检查标准输出，再保留一个真实的编译错误。分别核对是否避免顺带出题、是否在该学员需要前反复解释系统限制。缓存按同一账号、时间窗内供应商回执的命中输入 token 合计除以可计量输入 token 合计；另列缺回执的调用，回放字节数单列。

## 5. 迁移、启用和恢复顺序

1. 先核对当前工作树、迁移末尾与运行中任务，保护已有回执/数据。
2. 新增向后兼容结构与新合同，保持旧文档/摘录/Run 语义；不要原地改已应用迁移。
3. 先接后台准备/只读查询，再接新写入和客户端联合类型；确保旧客户端不会被突然发送无法解析的新类型。
4. 通知、决定和新绑定就绪后才允许当前路线迁移；后台发布不等于用户接受。
5. 在实际授权范围内做真实验收，明确配置/调用/部署的结果；写文档或配置存在不表示服务已更新。
6. 出问题时停止新准入/发布并保留已完成事实与待办，修复后从断点承接；不清理 UNKNOWN，不 destructive rollback。
