# 第四阶段 PRD：教材驱动的对话式学习完整交付

设计日期：2026-11-03。文档版本：1.2。阶段状态：实施中（进度核对：2026-11-12）；当前实现与分层验收见 [IMP 第 6 节](imp.md#6-状态维护)。

本文记录本阶段“为什么做、交付什么、怎样判定完成”。技术合同见 [spec](spec.md)，实施分解见 [imp](imp.md)。全项目范围仍以 [产品范围](../product/scope.md) 为准；实际实现与验证以 [仓库说明](../../README.md) 为准。

背景与问题保留设计时的起点，需求和退出条件不变；现有材料、工件、复习/主动教学及环境实现按当前进度记录。

2026-11-03 前端来源补充：用户确认以 LibreChat 前端源码为后续界面基础，独立引入后逐步适配；不引入其后台/执行系统，不减少现有模型配置、材料、路线/课时、练习、Gate 和复习能力。本项不改变 v1.2 的产品需求与退出条件；通用聊天适配不能代替对话内交互工件验收，技术边界见 SPEC S02.1、顺序见 IMP WP06。

## 1. 背景与问题

Leornian 已有通信、原生 Runtime、教学交付检查、动态计划/课时、概念与 Python 题包、审核、补救和 Gate 的实现基础，但下列缺口不能用已有接口或开发验收替代：

1. `knowledge` 当前主要管理学习者提供的摘录，没有完整教材接入、检索、覆盖判断和消费者闭环。
2. 0022 的“教学工件”实际是版本化文档，不是旧产品中嵌入 Tutor 对话、承载内容与操作的 Learning Artifact。
3. 资料到期或页面小改容易触发过量重新处理；当前前端仍提供“确认使用七天”，不符合正常学习周期。
4. 提示、直接答案、答疑分支、丰富交互类型、完整复习与主动教学尚未形成统一体验。
5. 单选与 Python 有界程序的成功不能代表所有语言、题型或整体掌握度已经完成。

用户要求以合格交付为目标，不以“最小跑通”、有效 JSON、目录、接口或测试数量宣称完成。

## 2. 产品目标与非目标

### 2.1 目标

- 学习者提出目标或提供原始材料后，系统自动准备教材、选材、检查、修复与发布，不要求学习者承担 RAG 工程操作。
- 学习者在 Tutor 对话内完成看题、编辑、作答、运行、提示、反馈和答疑；右侧只承担来源/文档阅读。
- 已开始的学习路线稳定绑定教材版本；检查日期到期不自动停课，新版由用户决定是否切换。
- 教学、评测、辅助使用、能力证据与复习有可追溯关系，不混成一个不透明的“掌握百分比”。
- 对正式声明支持的语言与交互类型逐项完成实际验收。
- 支持第三方依赖与框架的教材学习，并逐步提供受控多文件项目练习；不把框架教学等同于开放任意联网仓库。
- 所有模型通道由用户自行配置提供方、模型与 API 凭据，系统负责校验、按职责路由与安全保管。
- 仅支持用户本机代码执行，应用、本地后台和练习环境均在用户电脑；基础语言支持内置，实际环境按需一键准备。

### 2.2 非目标

- 不迁移旧 Aearn 学习记录、运行状态、预算、UNKNOWN 或权限。
- 不恢复 Sidecar、第二套 Agent Runtime、通用工作流平台或全面微服务拆分。
- 不提供任意宿主终端、宿主文件系统或通用仓库自动修改能力。
- 不提供或预留远程 Runner、托管代码执行服务器或公开多租户执行模式；外部模型 API 不属于远程代码执行。
- 本阶段不自动包含公开生产发布、收费服务开通、远程仓库创建或推送。
- 不以模型评价代替来源权限、真实执行、业务评分或人工独立掌握的证明。

## 3. 用户角色与核心旅程

### 3.1 角色

- 学习者：决定目标、确认路线、决定教材升级、实际作答/运行/开考，管理学习模式；一次性配置并启用所需模型通道，可轮换或撤销凭据。
- 系统：自动完成材料工程、题目供给、质量检查、修复、调度和状态恢复。
- 应用/环境管理：在用户电脑管理本地后台和隔离执行引擎；明确授权后自动准备课程环境，不要求学习者维护镜像、全局 SDK 或开发服务。
- 开发/运维者：维护提供方协议、运行环境与凭据保管设施，处理确实无法由系统恢复的基础设施问题；不要求学习者承担解析、索引或沙盒维护，也不代替各用户提供模型密钥。

### 3.2 完整旅程

1. 提出学习目标，系统检查教材与能力覆盖，自动补齐材料缺口。
2. 查看有依据的路线并明确确认；系统准备对应课时。
3. Tutor 引入知识，通过对话内工件组织演示和练习。
4. 学习者作答或显式运行，获得真实反馈；可请求提示、提问、修改或进入补救。
5. 满足条件后明确开考；系统依真实曝光和结果记录相应能力证据。
6. 根据真实学习与复习日志安排后续活动，在允许的模式下主动提出下一步。
7. 材料出现实质更新时收到影响明确的通知，自行决定立即更新、稍后决定或本轮保留旧版。
8. 暂停、断线或服务重启后，恢复原位置、版本、草稿和任务，不重复执行已发送的未知调用。

### 3.3 首次使用与按需环境

1. 安装 Leornian；应用管理自己的本地后台。首次实操前检测本机隔离引擎，缺少时引导安装，系统权限/重启要求明确提示，不默认已获管理员授权。
2. 学习某种语言时按需自动准备专用运行时/编译器及其锁定工具链依赖，不逐包询问，不一次安装全部语言，也不要求用户自行配置环境变量。
3. 制定路线时汇总完整环境需求，在确认路线的按钮气泡中一次询问额外课程库/框架安装；用户可同时确认并安装，或仅确认路线。默认只显示用途、主要环境及系统管理的专用隔离位置；依赖及版本、来源、资源估算与权限折叠展示，未知估算明确标注，不编造数字。
4. 用户可允许、稍后准备或调整路线；未同意不自动删目标，仍可读材料，但不能将未具备环境的练习标可运行或通过。
5. 授权后由系统自动下载、隔离构建与验证；同路线授权范围内的复用/重建不重复询问，超范围依赖、版本策略或权限变化再确认。
6. 点击运行后在本机执行、由本机业务模块评分并展示反馈。临时任务资源清理与可复用环境分开，不每题重装，不删除学习记录。

本地执行不等于完全离线：模型 API 与资料获取按原授权联网；不默认向外部服务发送完整项目，也不把代码交给远程 Runner。

## 4. 需求与验收条件

以下 P4-FR 编号由三份文档共用。全部为阶段内必须交付要求；交付包用于排序，不降低最终范围。

### P4-FR-01：教材接入与可追溯原文

- 支持登记的官方资料、可信公开材料、学习者有权使用的私有材料及既有摘录；首批格式包括 HTML、Markdown、文本型 PDF 和需要 OCR 的扫描页/图片。
- 保留文档版本、章节、段落、代码、表格与原文定位；抓取成功不等于材料可用。
- 验收：真实材料可回到精确版本和内容块；空文本、错序或关键代码缺失不能显示整份教材合格。

### P4-FR-02：以完成为目标的自动材料循环

- 自动发现缺口、选择已授权来源、解析、检查、定向修复、建立索引、验证和发布。
- 不要求用户选 OCR、切片、审核片段、补正格式、点击重试或点击发布。
- 不设任务总版数/总尝试次数上限；重复失败必须调整策略，批次让位不等于放弃任务。
- 验收：已知质量问题能自动修复或自动换可用来源；真实外部依赖缺失保持明确等待，不伪造完成。

### P4-FR-03：用户自配模型通道与千问候选

- Tutor、规划、课时、教学检查、讲评、作者、盲解、审核及 OCR、向量、重排序全部使用用户可配置的模型 Profile；可复用同一提供方凭据，不要求为每个角色重复填写密钥。
- OCR、向量、重排序采用独立操作协议，千问系列为优先候选，不让一个聊天模型包办全部职责。界面提供预置配置及能力校验，不让用户维护底层请求格式。
- 候选为 `qwen3.5-ocr`、`qwen3.7-text-embedding`、`qwen3.7-text-rerank`；向量/排序对照包括 `text-embedding-v4`、`qwen3-rerank`。
- 本用户已允许私有材料发送千问处理，并允许使用已有账号进行上述三个新增通道的收费开发与验收，无地域或费用上限。无需再次索取同项许可；实际账号/模型可用性仍须验证，不自动充值、升级或开通新收费服务。
- 正式组合依据真实材料质量、延迟、用量和费用选择；此开发授权不扩展到其他用户。其他用户启用时应明确材料外发范围、提供方及计费归属。
- 凭据按用户隔离，支持保存、连接测试、轮换、撤销/删除和生效范围提示；不回传明文，不写入公开历史、浏览器明文持久存储、模型上下文或学习者沙盒。缺失配置明确等待，不静默使用平台或其他用户密钥。
- 验收：实际用户配置驱动调用，配置版本、模型/区域、回执与用量可追溯；用户间凭据及私有材料隔离，撤销后无新派发，历史调用事实不改写；未配置通道不冒充已经实测。

### P4-FR-04：检索与材料覆盖

- 在权限、版本、主题、语言/框架及用途范围内进行词法与语义召回、融合和重排序。
- 给出“充分、部分、不足、不可用”及具体缺口；相似度和固定 top-k 不代替覆盖证明。
- 验收：中文正文、英文术语、代码标识符与跨表述问题均有实际检索验证；不足时回到自动补给。

### P4-FR-05：教材进入真实教学消费者

- 规划、课时、Tutor、作者及审核按各自职责消费精确材料证据，而非只在管理页展示检索结果。
- 规划不删除核心目标来掩盖材料缺口；生成和公开时重新检查绑定及用途。
- 验收：真实材料驱动一条“规划—确认—课时—Tutor—供题”链，引用可定位，失效权限不能被缓存绕过。

### P4-FR-06：分级变更与增量复核

- 区分元数据变化、措辞/排版等价变化、实质语义变化、权限/政策变化。
- 时间戳等非教学噪声不触发完整 OCR、全量向量化或全部审核；措辞变化定向检查，实质变化按精确依赖重验。
- 验收：复现旧项目“到期后仅时间戳或部分表述变化”的场景，证明没有重走无关流程，并展示复用/重跑理由。

### P4-FR-07：覆盖学习周期的稳定教材绑定

- 当前路线绑定精确教材版本，不随官网最新版本、全局语料指针或检查日期自动切换。
- 适用性复核初始默认 180 天；有预计完成时间时至少覆盖其后 30 天。稳定来源的后台变化检查初始默认约 30 天，可配置。
- 上述值是调度默认值，不是内容硬失效日；超期未学完或暂停后恢复不自动重置教材、题包或进度。
- 使用权限与保留策略独立记录；没有真实截止要求时不人为制造短期授权到期。
- 验收：跨过复核日期仍能继续原路线，检查任务自动运行，真实撤权和存储限制独立生效。

### P4-FR-08：更新通知与用户决定

- 系统自动准备并检查后继版本，通知列出差异、影响范围、建议与迁移代价。
- 用户选择“更新到新版、稍后决定、本轮保留旧版”；不选择时继续旧版，不因未读通知停课。
- 时间戳或已确认等价的小改不打扰用户；同一更新去重，保留旧版不无限屏蔽后续新的实质变化。
- 验收：通知已读/关闭不等于同意更新；接受操作幂等且检查当前路线版本，旧记录不覆盖。

### P4-FR-09：工件作为对话内交互单元

- Learning Artifact 是 Tutor 时间线条目，具有稳定身份、类型、内容引用、状态、版本与允许操作。
- 不是独立教学文档面板，不新增第二套评分或进度权威。
- 验收：知识检查和代码练习可在对话内完成，刷新恢复同一工件和最新结果，右侧仍为来源阅读。

### P4-FR-10：候选、工具与交付权限

- 服务端依据当前教学位置、已发布内容和实际能力构建精确候选；Tutor 只能选择合法组合。
- 工具查询/准备活动不直接授权执行、评分或发布；旧 Run 不因部署获得新增工具。
- 验收：伪造、跨用户、过期或未发布候选不能产生公开半条教学消息或可操作工件。

### P4-FR-11：作答、运行与反馈闭环

- 普通练习可按规则修改并创建新 Attempt；显式 Run 才执行，运行通过后无需第二次 Submit。
- Gate 保留明确开考、一次锁定、曝光及独立性条件，不能通过工件重跑绕过。
- 验收：正确、错误、重复操作、取消与迟到结果均有真实业务结果；模型讲评故障不丢失评分事实。

### P4-FR-12：提示、直接答案与曝光

- H1—H3 按顺序解锁，直接答案单独记录；重复查看与重放不重复写辅助记录。
- 所有实际展示的提示、答案、讲评、预览材料进入对应曝光事实，辅助成功不冒充独立掌握。
- 验收：需要新情境检验时供给已审、未见的后继，不能清空旧记录或刷同一失败报告。

### P4-FR-13：丰富工件类型

- 补齐知识检查、代码练习、执行结果、代码评审、SQL、交互演示、HTML/CSS 预览和来源定位。
- 框架/第三方库的练习以课程声明的固定版本、受控多文件模板、锁定依赖和真实测试为单位开放；尚未具备运行资格时明确准备状态，不能用生成了项目文件或教材讲解代替可执行练习验收。
- 演示/阅读/预览完成不是独立评分；可评分类型须具备实际 scorer 与当前运行资格。
- 验收：每类有完整可用交互，不以占位卡片或语言注册项代替完成；预览不能在主 DOM 执行不可信脚本。

### P4-FR-14：教学会话、答疑与主线恢复

- 支持引导学习和自由阅读/问答；阻塞工件期间普通消息进入锚定工件的一层答疑分支。
- 用户消息优先，完成后可折叠“答疑 · N 轮”并回到主线；主题切换采用明确控制。
- 验收：一个会话只有一个可发布前台轮次，工件事件/定时器不抢占用户问题，不重复推进。

### P4-FR-15：按证据区分学习能力

- 概念理解、实际执行、新情境应用分别保存证据；Learning 派生当前状态。
- 保留范围、策略、辅助、曝光、版本和时间，不把单次题目通过扩张成整门语言掌握。
- 验收：Tutor、工件、阅读和自评均不能直接写掌握度；旧成功/失败不因新版覆盖消失。

### P4-FR-16：真实复习与 FSRS

- 将固定 1/3/7 天自评安排升级为基于真实日志的复习；保存算法、参数与状态版本。
- 复习自评、客观作答和独立评测分别记录，FSRS 记忆状态不替代编程能力。
- 验收：到期任务可进入对话工件，完成后正确更新安排；旧自评不被重写成客观评分或虚构训练数据。

### P4-FR-17：可控的主动教学

- 允许的引导模式下，根据持久业务事件或到期复习创建教学意图；自由问答默认不自行连续推进。
- 支持暂停/恢复、时段偏好和取消；不自动开考、作答、确认路线或切换教材。
- 验收：活动前台、用户消息、考试和暂停能阻止不适当续行；同一触发事实不重复发消息。

### P4-FR-18：语言与执行能力矩阵

- 以 Python、JavaScript、TypeScript、SQL、Java、Go、C#、HTML/CSS 公开课程范围逐项对照，不把某个 Runner 注册项当作已交付课程。
- 先交付可复用的语言/方言/项目 Profile 基座，再逐项完成课程链。基座完成与课程完成分别记录，先做基座不等于八组课程同时完成，也不静默缩减最终范围。
- 语言支持规则、可信环境配方和测试协议内置；运行时/编译器/依赖作为按需环境包，安装到本机专用隔离环境，不修改全局 SDK，不要求用户手工执行安装命令。
- 路线生成/确认不隐含安装授权；环境需求及用户决定持久化，授权范围内自动准备和修复，超范围变化再确认。安装成功仍须通过环境、题目与评分资格检查。
- SQL 首批按 MySQL、PostgreSQL、SQLite 设计独立方言 Profile；SQL Server、Oracle 等单列扩展状态，不声称通用 SQL 全兼容。Rust/C++ 进入编译环境适配评估，不因旧注册项或本次环境咨询自动变成已确认的完整课程交付。
- 框架学习与受控项目练习是目标能力；执行任意外来仓库、任意安装脚本、开放网络/宿主权限不作为默认能力。不提供远程执行备用模式，本机执行仍须验证隔离、资源和清理。
- 每项列明材料、课时、题型、运行/评分 Profile、工件、供题审核、Gate、补救及复习状态。
- 验收：正式声明支持的组合均有真实端到端证据；SQL 标明方言，HTML/CSS 预览与正式检查分离，未完成项不标通过。

### P4-FR-19：恢复、隐私与历史保护

- 长任务持久化，事务外调用，短事务提交；当前授权、外部调用事实、业务完成分别判断。
- UNKNOWN 不自动重发；取消不伪造外部模型或本机执行已停止；迟到结果保留但不自动推进失效任务。
- 验收：重启、重复投递、版本竞争、权限变化、跨用户读取均维护原保证；公开数据无私有答案、测试、推理或凭据。

### P4-FR-20：分层真实验收与交付说明

- 自动化合同/数据库测试、真实模型、真实 Runner、实际界面与原生桌面分别说明。
- 记录首版/最终合格情况、修订原因、耗时、输入/生成/推理用量、未知用量与未解决问题。
- 验收：阶段要求逐项满足，不以样本通过、HTTP 200、测试数量或开发者模拟作答声称整体良率、人类掌握或产品全量完成。

## 6. 自动化与用户决策的边界

| 系统自动完成 | 用户明确决定 |
|---|---|
| 提供方预置、协议/能力校验、凭据安全保管和按职责路由 | 自配并启用模型凭据、外发范围、轮换或撤销 |
| 本机引擎检测、依赖分析；已授权范围内下载/构建/验证、环境复用和恢复 | 系统组件安装权限、路线环境安装授权、超范围依赖/权限变更 |
| 来源发现/处理、检查、补正、重建索引、合格发布、通知投递 | 学习目标与必要原始材料 |
| 已知质量问题的诊断、修复、依赖恢复与任务承接 | 确认路线、是否切换到新版教材 |
| 到期检查、差异分类、影响分析、准备后继 | 作答、显式运行、开考、辅助请求 |
| 允许模式中的教学意图安排 | 学习模式、暂停/恢复及通知偏好 |

访问撤销或真实执行安全故障不是教材升级选项，不能由“保留旧版”绕过。系统只限制对应范围，保留历史和其他可继续工作。

## 7. 阶段验收场景

| 场景 | 必须观察到的结果 |
|---|---|
| 用户配置/轮换/撤销模型凭据 | 各职责按所选 Profile 调用；明文不回传、不跨用户、不进入沙盒；撤销不改写或重发旧 UNKNOWN |
| 首次使用且未装课程工具链 | 明确检测/引导底层引擎，系统引擎安装先取得授权，所选语言及配套工具链按需自动准备；不要求手工启动后台或改全局 SDK |
| 路线要求新框架，用户暂未同意 | 保留路线与教材，环境等待授权，不下载、不反复弹窗，不伪报可运行 |
| 同范围重建或超范围新增依赖 | 前者自动恢复/复用；后者重新展示并确认，旧授权不能任意扩大 |
| 真教材首次接入 | 自动解析/必要 OCR、检索与引用、路线/课时实际消费成功 |
| 已知解析或覆盖失败 | 自动调整策略/补来源后继续；不要求用户审核或手工重启 |
| 到期后仅页脚时间戳变化 | 更新检查记录，复用已成立内容结果，不全量 OCR/向量化/审核 |
| 一段等价改写或一处实质变化 | 定向处理；精确说明复用和影响，不全体重跑 |
| 复核窗口已过但学习未完 | 当前绑定继续可用，后台检查，不因日期重置进度 |
| 新版通知未处理/保留旧版 | 继续原路线，不强制切换或反复弹同一通知 |
| 接受更新遇到并发版本变化 | 冲突可解释，重新读取当前状态，不静默覆盖 |
| 对话内知识检查与代码练习 | 操作—评分—反馈—教学续行完成，刷新不重做 |
| 提示/直接答案后的正确作答 | 辅助和曝光真实保存，不计无辅助独立掌握 |
| 运行/模型调用中断、取消和迟到 | 不重复发送未知调用，不丢结果，不失权续行 |
| 答疑/考试/自由阅读期间触发后台 | 用户和考试优先，无不合模式的自动教学 |
| 真实复习与语言组合 | 调度、交互、评分/自评与证据层次清晰，矩阵可追溯 |
| 多文件/依赖/框架练习 | 固定环境下真实构建、测试与评分；依赖准备和学习者执行隔离，资源/清理/网络边界成立 |

## 8. 完成定义

本阶段完成须同时满足全部 P4-FR、各交付包退出条件与对应真实验收。已知质量阻断、未配置通道、未完成语言、未通过界面或原生验收必须如实列出；不能通过降低要求或省略范围将阶段标为完成。
