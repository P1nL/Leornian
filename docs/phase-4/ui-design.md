# 直接使用 LibreChat UI：功能承载方案

日期：2026-11-08。版本：0.8，含学习路线侧栏、节点顺序学习、计划创建过渡和流式教学展示。

**直接使用 LibreChat 的界面，不另做一套学习管理系统。先把功能放进现有界面，只有确实无法承载时才新增页面。**

本版替代 v0.1 的 13 页拆分方案，保留用户已修改的要求：**顶部仅显示当前学习，不增加节点、路线版本、证据、环境等常驻状态条。**

需求仍以第四阶段 [PRD](prd.md)、[spec](spec.md)、[IMP](imp.md) v1.2 为准。本稿决定界面归属与迁移基准，不缩减阶段功能。所称“已有”指本机固定版本 LibreChat 的前端组件存在；5180 已接真实业务，5182 为独立演示，具体能力与验收见根 README。

## 0. 已确认的前端基准

2026-11-07 用户明确选择 **5180 当前 LibreChat 前端**。后续真实业务接入以这套界面为准，不以另一个宿主已经接通后台为由替换其页面。

- **保留的界面**：当前对话外壳、侧栏与导航、欢迎页、输入与附件体验、顶部学习菜单、设置窗口、来源面板，以及用户正在打磨的工件组件、样式和动效。新增必要功能优先使用本方案已有承载位置；大幅布局或交互调整先与用户确认。
- **迁移的内容**：将演示数据、样例状态和模拟回执逐项替换为本人真实身份、公开合同、快照/SSE、持久任务及原 owner 动作。复用 5181 已验证的权限、请求幂等、版本、草稿、取消与回执适配，保留 5180 的界面组装。
- **入口的职责**：5180 是真实基准界面与持续修改入口；5181 是工程联调入口，其独立开始页、输入框或菜单不替换产品设计；5178 保留尚未迁移的旧功能。原演示与工件一览移至 5182，数据不进入真实记录。端口本身不是最终产品结构。
- **真实状态的来源**：5180 的演示身份、样例成绩和 `demo-state` 不导入真实学习记录。真实接线继续使用 Leornian 身份、来源权限、Assessment/Execution 和原 Runtime，正式结果来自原 owner 的已提交回执。

同日按用户“进行接线”完成核心适配并切换 5180。欢迎页、输入框及任务弹层共用 `LearningChrome`；真实宿主以 `BaselineLearning` 提供数据/回调，工件仍使用原 `NativeArtifacts`。新目标、本人配置、草稿、原回执和任务取消已接，文件上传、完整路线/课时、复习作答及完整模型编辑仍按 WP06 迁移。实施与分层验收清单见 IMP BA01—BA12。

## 1. 用户看到的产品

打开后仍然是 LibreChat：

- 左侧：创建新学习计划、最近、学习。学习入口按路线文件夹展开节点。
- 中间：当前学习的对话，以及需要操作时出现的练习、路线或确认内容。
- 底部：原有输入框和附件按钮。
- 右侧：点击引用后才打开的教材/来源阅读面板，默认不占空间。
- 设置：原有设置窗口，补充模型配置并适配本机执行设置。

### 学习计划与节点对话

- 输入框居中，桌面最大宽度 880 px；移除输入区和页脚的本机 Tutor 固定文案。
- 创建计划保留侧栏图标入口，学习列表不重复放创建按钮。每个路线文件夹提供气泡菜单，支持重命名和确认删除；删除从学习与最近中移除，历史对话及调用记录保留。
- 最近列表的对话删除使用 `DELETE /v1/conversations/{id}/recent-entry`，只持久移除本人最近入口，不删除学习计划、不取消后台请求；仍可从学习路线打开原会话。快照保留 `Conversation.hidden_from_recents` 与原记录，最近列表据此过滤。重复删除返回原状态，首次移除提交 `tutor.conversation_hidden` 事件。
- 输入框下方不常驻教学处理中提示；实际结果未知时，在回复区提供明确的结束原等待并重新发送入口。
- 创建计划先保存目标并进入路线讨论会话。后续消息继续讨论目标、基础、时间与范围；模型可追问必要信息，信息充分后输出完整路线草案。讨论请求不启动节点教学。
- 确认路线和从侧栏进入节点都只打开相应节点，不代发用户消息。引导模式下，首次进入先留 8 秒给用户提问；没有插话就由 Tutor 讲第一小段。再次进入恢复该节点的对话停点、输入草稿及练习。
- 上一段正文完整显示且确实可以续讲时，沿输入框外边框走一圈。鼠标移入、点按、触摸、Tab 进入、拼音组合或有草稿均暂停；程序自动聚焦不算接手。离开且没有草稿才给新的完整窗口。减少动态效果时以静态边框和文字提示代替走线。等待答复、实际操作、收尾、自由阅读、暂停或页面在后台时不计时。
- 路线按节点顺序开放。前序节点有本人已交付的学习对话，或学员在收尾讲解后明确选择“结束本节，进入下一节”，才可进入后继节点。收尾不自动跳转，纯听课也不必为了导航回答一道题。Tutor 按当前路线修订分别投影 `studied_nodes` 与 `ended_nodes`；自动续讲和导航均不写掌握进度。
- 计划创建步骤保留原请求标识；刷新或结果待核对时继续读取原回执。

### 思考与流式回复

- 教学类 Chat 模型默认开启思考；向量、OCR、重排保持各自独立协议。DeepSeek 使用 `thinking`，DashScope Chat 使用 `enable_thinking`。
- Runtime 使用提供方 SSE 接收内容、私有推理与工具参数，完整结束后组装原协议回执。中断或缺少结束帧保持 UNKNOWN。
- 思考区展示模型返回并过滤后的可展示文本，内部提示、凭据、工具协议与代码围栏经过过滤；独立检查角色的推理不进入学习对话。`tutor.thinking` 的 `thinking_summary` 是阶段状态，`thinking_text` 是累计的可展示文本，两者分开处理。
- 阶段状态不作为思考内容，不提供空的展开按钮；收到实际文本后才复用原思考展开组件。思考事件立即进入流式状态，不再等正文开始后才显示。
- 展示直接复用 LibreChat 的 `Reasoning` 和 `Markdown`，保留原有展开、复制及 Markdown/代码渲染行为。
- 思考与流式回复位于消息滚动区域末尾，按左侧 Tutor 消息行排版，随对话滚动；不占输入框上方的固定区域。任务完成后移除临时行，由正式消息的原生思考内容部分承接，刷新后仍可展开。已有完整回执的旧回复通过同一过滤器只读投影，不补发模型请求。
- 回复继续通过既有交付检查；检查通过后，`tutor.succeeded` 的公开 `reply_text` 由 SSE 分段交付为 `tutor.reply_delta`，最后同步正式消息与工件。正文分段开始于检查通过后；模型生成期间展示思考状态和摘要。

不增加一排“目标、路线、材料、证据、复习、任务、更新、环境中心”导航。学习者主要做四件事：**说想学什么、上传材料、完成练习、继续学习。**

## 2. 现有 LibreChat UI 可以承担什么

“沿用”保留布局和操作习惯；“适配”更换业务数据和动作；“补充”只在现有位置增加必要内容，不另开页面。

| 现有 UI | 承载的学习功能 | 所需改动 |
|---|---|---|
| 新对话欢迎页、输入框 | 输入学习目标，通过问答补充基础、用途和学习时间 | 适配目标保存/会话创建；不先填一套建档表单 |
| 左侧历史对话列表 | 找回学习目标、恢复同一段学习、切换已有学习 | 接入 Leornian 目标及关联会话；不新建一套 Projects 数据 |
| 原有搜索入口和结果界面 | 查找旧对话、讲解和学习记录 | 接入本人可读的真实查询；不能只搜索首屏后称全部历史 |
| 原有顶部区域 | 显示当前学习，使用原有菜单打开路线、学习记录或复习入口 | 不新增学习控制台；必要入口放菜单，不堆工具栏 |
| 原有模型选择器 | 选择本人已配置且获准用于教学的聊天模型 | 对接实际模型配置及生效范围；其他职责不要求逐轮选择 |
| 消息正文、Markdown、代码块 | Tutor 问答、课时讲解、讲评、学习建议、只读历史文档 | 沿用渲染外观，内容取自真实公开结果 |
| 消息内容区域 | 路线草案、路线确认、练习、考试、结果和答疑 | 补充结构化学习内容与合法按钮，见第 3 节 |
| 输入框、附件及拖放 | 提问、追问、提交学习材料、粘贴文本或官方链接 | 接入材料流程；解析、OCR、检索等在后台自动完成 |
| “我的文件”窗口 | 查看上传材料、处理状态、关联学习、版本和使用权限 | 适配现有文件列表，详情按需展开；不另建材料库页面 |
| 引用和可展开侧面板 | 阅读教材、查看精确来源、定位引用片段 | 替换为只读文档阅读内容；不把练习编辑器移到右侧 |
| 当前回合的处理状态/活动展示 | 显示正在准备、检查、等待配置或结果未知 | 展示真实状态；内部循环不变成用户操作步骤 |
| 顶部后台任务按钮及弹层 | 查看当前学习的持久任务、等待原因、处理入口和安全历史 | 复用列表/展开样式，替换原工具/子代理任务数据和操作 |
| 原有菜单、按钮和对话框 | 路线确认、教材更新决定、环境安装授权 | 补充对应摘要和明确操作；不为每个决定建一页 |
| 设置窗口的通用/聊天设置 | 主题、语言、字号、输入习惯、学习方式和提醒偏好 | 尽量沿用，只保留已支持且有作用的选项 |
| 设置窗口的 API Key/连接相关区域 | 本人提供方、密钥、模型及连接测试 | 合并为易用的“模型配置”，不拆成多个管理页面 |
| 设置中的代码环境区域 | 本机引擎状态、课程环境准备、已授权范围 | 改为本机专用流程，不沿用远程 Worker 配对或手工命令 |

例如“查看学习记录”应有可点击入口，直接读取已有事实，不要求用户必须找 AI 问一遍。打开记录、来源、任务详情不触发新的模型或代码调用。

## 3. 原界面需要补充的局部内容

### 3.1 对话里的学习交互

普通讲解直接用原消息，不把每条回复都做成卡片。只有涉及结构化信息、作答或明确决定时增加交互。

| 功能 | 放在哪里 | 用户操作 |
|---|---|---|
| 学习路线 | Tutor 消息内的路线摘要，可展开完整内容和历史版本 | 确认当前草案，或直接输入修改要求 |
| 知识检查 | 当前消息内 | 单/多选、预测、排序、范围定位或简答；明确提交本次回答 |
| 代码/受控项目练习 | 当前消息内的三分区工作台，可整体放大 | 左侧题目，右上编辑器，右下用例/结果；编写后显式“运行并检查”，普通练习不再二次提交 |
| SQL 练习 | 同一工作台，左侧标签页包含 Schema | 在固定方言/隔离数据下显式运行，结果对应当时的输入和方言 |
| 执行结果、代码评审 | 对应练习后面的结果内容，可展开公开详情 | 查看错误、修改、继续提问；不跳转评分后台 |
| 演示、HTML/CSS 预览 | 对话内的受限交互区 | 操作或预览；预览和正式评分分开 |
| 正式考试 | 对话内的考试内容 | 先明确开考，再整组作答和一次提交；不是普通练习试跑 |
| 提示、答案、补救、新情境 | 对应题目附近，仅出现当前允许的操作 | 按需请求；不清空旧辅助或失败后重做成“独立通过” |
| 答疑 | 原输入框和锚定当前练习的一层问答 | 正常提问；回主线后折叠为“答疑 · N 轮” |
| 复习 | 当前学习中的复习提示/菜单入口，进入同一类练习内容 | 开始复习并作答，不另学一种复习页面 |
| 学习证据 | 当前学习菜单或结果中的“学习记录”展开内容 | 看实际通过、仍需练习和辅助情况，回到原结果 |
| 旧课时和教学文档 | 原消息中的文档链接/摘要，正文使用阅读面板 | 阅读精确版本、查看历史、提出修订 |

2026-11-06 的 WP08 切片已接原生呈现：原“当前学习与路线”接显式模式/暂停/恢复/主题/返回控制，原输入框按服务端 focus/revision 发送，读取未明或失败保留草稿并阻止误发。消息桥接读完原公开历史分页，按原分支标识分组，继续调用原 Row/Markdown，用户右侧、Tutor 左侧；活动展开，明确返回或改主题后默认折叠为“答疑 · N 轮”，可只读展开旧历史。分组沿原消息列宽度及现有 Disclosure/Action，不另造气泡或答疑样式。独立 8096/5186 真实对话/SSE 已验同锚点两轮答疑、B 草稿刷新、暂停后明确问题和主题退役；实际 391 像素无页面横向溢出，默认视口已恢复。六个控制回执、三份原 owner 接触与工件 revision 1 分别保留，没有作答/Attempt/正式进度或未请求提示解锁。作者/检查仍为离线 HTTP，持久意图/优先级/自动续行和全场景仍待实施，不新增第九类工件、第 32 个组件或把局部浏览器证据算作 WP08 完成；共享 renderer/CSS/动效/示例和用户 5180 保持不变。

同日后续接入结果后续教学：沿原菜单增加默认关闭的显式策略，说明开启后会使用本人配置的模型；自由阅读不自动续讲，暂停保留待办。现有 Disclosure 展示“后续教学队列（最近20条）”、实际等待原因与原 Run 状态；取消使用原提交回执，UNKNOWN 不重发。已识别自动 Run 时，原输入框和控制仍能明确接管，普通 Run 保持互斥；pending 不投影，接受后只用原 Tutor 消息，不把内部指令画成用户气泡。新 8097/5187 以真实 API/数据库/原 Runtime/SSE 验暂停提交 B、恢复后的唯一续讲与刷新；原错误评分、原草稿/历史及零正式进度保留，391 像素队列/长任务 ID 无横向溢出，默认视口恢复。作者/检查仍离线 HTTP且显式驱动原扫描；不改变共享工件样式、31 组件目录或用户 5180，不据此完成定时/后台主动教学、真实供应商或全部场景。

这些交互仍用 LibreChat 的字体族、主题与消息布局。自定义工件统一使用 1px 细边框和轻微区别于聊天画布的主题底色；标题、内容区与操作区由细分隔线和内边距划分，标题旁不再常驻文字状态。正文 16px、代码 15px、标题 18px（以 rem 定义）；删去重复说明，只保留任务内容、操作、结果和必要授权/未知/旧稿提醒。它们是必须补的教学控件，**不是 LibreChat 原生已经具备正式评分、考试和进度权威**。

新增工件的按钮采用图标优先的细边框圆形/胶囊风格。2026-11-05 用户修订：运行、提交、更新预览、开考、路线确认、安装授权、自评以及设置中的保存/测试等重要按钮，统一采用 Phosphor Regular 图标和圆形外壳，不再保留可见文字；悬停或键盘聚焦显示动作/状态提示，保留完整可访问名称。文件名、用例编号、提示等级与功能标签仍保留文字。普通图标操作沿用现有图标，diff 与参数加减控件也采用 Phosphor。

重要按钮保留外壳悬停/按压回弹和颜色过渡，图标固定为 20px 的居中层，不跟随按钮缩放、位移或旋转替换；状态切换仅交叉淡入，忙碌图标的自转仅表达忙碌，不跟随按钮形变。完成态采用 Phosphor 勾图标，不加装饰圆环。普通带文字按钮保留字符折叠效果。排序操作后仍清除被移动按钮的悬停反馈。完成标记由已有交互结果驱动，不因点击或动画结束自动成功；错误回答显示提醒图标，旧稿、取消和 UNKNOWN 不显示当前运行成功。不改上游原生导航。图标路径来自官方 `phosphor-icons/core/assets/regular`，内置于 `PhosphorIcons.tsx`，保留 MIT 许可并随预览构建输出，不使用运行时 CDN。

工作台功能、用例/结果、公开用例、项目文件及 HTML/CSS 标签页统一使用滑动选中层和内容淡入位移；悬停不改背景，选中层采用不过冲的弹簧，避免末端产生临时横向滚动条。超长标签栏仍支持横向滚动及方向键，不显示轨道。非活动面板保留挂载以保存编辑状态，同时用 inert 和 aria-hidden 排除交互及读屏。

容器内说明、历史、答疑及源码定位统一使用可收起区域：展开/折叠有内容尺寸过渡与箭头旋转，收起后不可聚焦或读屏。右侧来源阅读面板加入进入动画，一览页同步过渡主区/侧栏分栏比例；关闭时保留退场所需的引用快照，不因此重新取得材料权限。相邻代码示例及 Markdown 代码块留出 12px 间隔。单选/复选保留原生输入语义，添加点/勾缩放和选中底色过渡。减少动态效果时取消弹跳、折叠、旋转与位移，只保留短淡入淡出和即时状态；本轮仅桌面端，不新增移动适配。

长路线、代码和考试可在原区域展开或放大；不因内容长就新增一个独立管理页面。

代码工作台参考 LeetCode 的操作布局，不复制社区、登录或无实际能力的入口。左侧顶部以标签页收纳“题目描述、提示答疑、代码评审、运行记录”；受控项目将评审位置替换为环境配置，SQL 提供表结构。右上依次是代码标题、语言/文件、可编辑内容和底部操作栏，**运行按钮固定在编辑器右下角**，不放在整个工件的最底部；右下“测试用例 / 运行结果”切换，明确运行后展示结果。宽屏可拖动左右和上下分隔线，窄屏按题目、编辑器、结果顺序堆叠，保留同一份草稿、授权限制和历史。放大的是整个工作台，不占用来源阅读侧栏。这一布局属于离线前端演示，不把固定样例反馈当作真实执行或评分。

HTML/CSS 受限预览采用左右分栏：左侧顶部以 HTML / CSS 标签切换编辑内容，左侧底部明确更新预览；右侧直接显示隔离后的效果。两栏之间可调整宽度，保留原编辑器放大入口和草稿。编辑不自动刷新效果，不改变无脚本、无网络、无宿主权限的边界。

#### 工件完整清单

spec S09–S11 的呈现类型是以下 **8 类**，不是只有代码和 SQL。全部放在原消息流内；来源阅读借用原右侧容器，窄屏使用原对话框。

| 工件 | 类型标识 | 前端应展示的内容 |
|---|---|---|
| 知识检查 | `knowledge_check` | 单选、多选、预测、排序、代码范围定位、简答；作答、锁定回答和参考讲评 |
| 代码工作区 | `code_workspace` | 单文件代码及受控多文件项目；编辑、放大、运行入口、只读测试/锁定依赖 |
| 执行结果 | `execution_result` | 对应输入的输出、错误和公开检查结果；保留旧结果，不把新草稿当作已通过 |
| 代码评审 | `code_review` | 问题定位、建议修订、放回编辑区；阅读评审不等于执行或通过 |
| SQL 工作区 | `sql_workspace` | 方言、查询编辑、Schema 和结果表；复制表名不自动插入或运行 |
| 交互演示 | `demo` | 分步观察、播放/暂停和事件反馈；看过不等于独立掌握 |
| 受限预览 | `restricted_preview` | HTML/CSS 编辑与隔离预览；没有脚本、外部资源或宿主权限，不替代正式检查 |
| 来源定位 | `source_locator` | 消息或工件内的轻量引用入口，不单独套工件容器；精确文档、版本、章节和原文块保持绑定，接受新版不改写旧引用 |

路线确认、考试、提示/答案、补救与新情境、答疑、复习、学习记录、材料更新和环境授权是周边业务流程，不新增第九种工件。普通讲解和旧教学文档继续使用原消息/阅读容器。前端样例不会将这些流程的展示当成服务端评分、进度或执行资格。

### 3.2 两组必要的设置内容

仍使用 LibreChat 原设置窗口，不新增设置站点。

**模型配置**

- 常用层只要求选择提供方、填写本人 API Key、选择教学模型。
- 需要材料处理时，补充 OCR、向量和重排序模型；同一提供方可复用密钥。
- 用明确的推荐配置覆盖各教学职责，不要求普通用户逐个理解作者、盲解、审核等内部角色。
- 职责映射、容量、超时等放“高级设置”，仍有入口，但不作为日常使用门槛。
- 保存配置不自动发起计费测试；测试、轮换、撤销和私有材料外发用途在同一处处理。

**本机执行**

- 复用已有代码环境设置的容器，显示本机引擎是否可用和课程环境状态。
- 正常使用时自动准备已授权范围；需要系统权限、重启或扩大依赖范围时再提示。
- 不要求用户配远程 Runner、复制 Worker 命令、手动启动后台或修改全局 SDK。
- 具体课程的安装授权在对应练习附近发起，设置中可回看和管理，不再跳到“环境中心”。

学习模式、主动教学暂停和时段偏好放原聊天/通知设置；不再独立拆一组管理页。

### 3.3 材料和授权的必要信息

上传时只说明需要本人决定的用途及外发范围；真实使用/保留期限按需填写，不默认七天过期。后续解析、检查、修复和发布不要求用户逐项确认。

“我的文件”中保留查看版本、关联学习、下载原文、查看权限及撤销的入口；这些操作不挤进右侧只读阅读区。

教材实质更新时，在对话显示变化和影响摘要，提供“更新、稍后、本轮保留旧版”；长比较使用原有展开/对话框容器。已读或关闭不等于同意，接受时检查当前版本。

制定路线时汇总完整环境需求，基础语言及锁定工具链依赖自动准备；额外课程框架在确认路线的按钮气泡中一次询问，提供“确认路线并安装”和“仅确认路线”。默认只显示用途、主要环境及系统管理隔离存储，完整依赖、版本/来源、权限和已知资源估算折叠展示，不要求用户选择目录。确认后从“学习环境”按钮查看实际状态或稍后安装；同范围复用不重复询问，扩大范围再确认，UNKNOWN 先核对原操作。系统引擎安装权限与课程依赖授权分别处理。

## 5. 用户的使用流程

**开始学习**：打开 LibreChat → 输入“我想学习…… ” → Tutor 补问必要信息并给出路线 → 在对话确认 → 开始讲解和练习。

**带材料学习**：点击附件或拖入材料 → 明确材料用途 → 系统自动准备 → Tutor 在对话中使用 → 点击引用阅读原文。

**练习需要框架**：在对话看到练习 → 阅读安装范围并明确同意 → 自动准备 → 原位置运行练习。拒绝或稍后不丢目标、材料和可继续阅读的内容。

**下次继续**：从原历史列表打开同一学习 → 恢复真实消息、结果和待处理事项 → 继续学习或开始复习。

- 不照搬上游的重生成、删除、重试、远程执行和任意预览行为；没有相同业务语义的操作不开放。

### 8.5 当前产品界面的组件工作台

在仓库根目录运行：

```sh
pnpm librechat:components
```

工作台默认地址为 `http://127.0.0.1:5183/__components`。可用 `pnpm librechat:components 5190` 指定其他空闲端口。5180 继续是产品入口，根 `dev` / `build` 及 connected 命令保持原用途。

目录按页面与布局、身份与开始、导航与路线、顶栏与任务、消息与教学、输入与附件、路线与学习记录、学习工件、材料与来源、设置与模型、公共控件与反馈、样式与动效分为 12 个区域，共 78 个预览入口。工件组件样例沿用既有目录；原生业务面板、正式考核、新情境检查、分级提示、全局通知和快捷键弹窗也有对应入口。

使用流程：

1. 在左侧选择组件，切换其默认、空内容、加载、处理中、错误或其他适用状态。
2. 调整浅色/深色主题和画布宽度；画布自动按可用空间缩放，控件仍按所选宽度布局。
3. 在右侧查看组件、业务接线与样式文件，修改实际文件并保存。Vite 会更新对应组件或 CSS。
4. 点击“点选元素”，再点击画布中的文字、图标或控件，查看所属组件、选择器和源码位置。
5. 通过“完整页面”检查区域协作，通过“单独打开”使用完整浏览器空间；“重置预览”恢复该入口的初始样例。

修改预览目录或本地响应代码后重新启动工作台；组件和 CSS 的日常修改支持热更新。

源码归属：

| 修改对象 | 位置 |
|---|---|
| 欢迎、登录和输入框外观 | `apps/librechat/LearningChrome.tsx` |
