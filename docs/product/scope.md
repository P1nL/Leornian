# Leornian 产品范围

## 产品目标

面向编程学习者，把学习目标、计划、课时、Tutor 对话、代码练习、反馈、进度与复习组织成完整学习体验。

这是整个项目的重新设计，不是仅修复旧 Aearn 的某条题库链路。分阶段实现不等于缩减最终产品目标。

当前已交付本地身份、目标、原生 Tutor、动态路线/正文、五槽概念与 Python 执行题质量链、补救/精确后继/缺题供给、回执讲评、实际曝光绑定的概念/执行 Gate、固定样例评测、来源与基础复习。概念题包已有真实供应商生成/审核/修订；原真实 Gate 质量阻断保留。代码后继与 Gate 有实际 Docker/真实库正向验证；新 Python 真实生成两版经过执行和六审，仍保持变化要求、不发布。概念、执行与完整掌握度不互相替代。

2026-11-02：第四阶段设计见 [PRD](../phase-4/prd.md)、[spec](../phase-4/spec.md) 和 [IMP](../phase-4/imp.md)。它补回完整教材 RAG，并纠正“工件”为 Tutor 对话内的教学交互单元。当前来源摘录、0022 的版本化教学文档和固定间隔复习只是已有实现，不代表这些目标已交付。

## 目标能力

- 学习者身份、偏好与数据归属。
- 学习目标、版本化计划、课时阅读、学习进度与掌握度。
- Tutor 多轮教学、提示、教学工件与中断后的明确续行。
- 可信材料检索、来源引用、版本和当前有效性管理。
- 动态题目与题包供给、质量审核、修订和受控发布。
- 练习、作答、反馈、评测 Gate 与受限代码运行。
- 复习安排、主动教学，各类学习工件与语言执行能力。

更细的教学规则、语言矩阵、审核角色与题包条件，在对应切片中从旧产品要求逐项核对；不能默认降低要求，也不把旧内部实现当作必须复制的规格。

## 已确认范围

- 仓库和项目名称：Leornian。
- 独立新仓库、独立新库，暂不迁移旧学习记录和运行状态。
- 直接移除 Sidecar，采用唯一原生 Agent Runtime。
- 模块化后端与清晰公开接口，后台任务和隔离执行服务独立运行。
- 2026-11-03 确认仅支持用户本机执行：桌面、本地后台、数据与 Runner 均在用户电脑，不提供或预留远程 Runner。进程分离不代表跨机器部署，外部模型 API 不属于代码执行服务器。
- 旧仓库、旧库与历史记录保持不变。

## 当前不包含

- 旧数据迁移、旧运行状态兼容或旧现场恢复。
- 任意操作宿主终端、完整代码仓库自动修改等通用编程 Agent 能力。
- 微服务全面拆分、通用工作流平台或全量事件溯源。
- 公开发布、生产部署、自动开通付费资源。
- 远程代码执行服务、托管执行服务器或公开多租户执行平台；不作为本地模式的备用分支。

## 推进方式

2026-11-01：教学、规划和课时也以合格交付为目标，不以一次有效 JSON 或最小短回复算完成。服务端绑定当前目标/精确节点/公开反馈，候选经过独立检查后才交付；已知问题持续诊断修复，不设总尝试次数上限。模型容量、输出预留与总超时按阶段解析，长请求独立心跳。大份实际教学/曝光上下文分批完整比较并检查组合风险，不通过截掉历史制造独立性。计划确认、开考、作答和评分/掌握度仍是独立业务条件。

2026-11-01：生题需求提出后的正常流程不设人工操作门槛。新概念/Python 题包及缺题供给默认自动生成、盲解/执行、六审、按报告修订和合格发布；用户不负责审核票、版本推进或发布按钮。以合格交付为目标，取消固定修订版数和补正次数上限；质量条件不放宽。任务级取消覆盖全部后继，历史选择不强制跳回最新版。依赖失效等待恢复，未知调用不盲目重发，完整迟到回执可重验后承接。旧手动记录保留，不追溯重跑。这里自动化的是生题，不是代替学习者作答、开考或生成掌握度。以下旧手动发布表述对新自动包由服务端策略执行。

1. 先实现通信与持久执行基础，明确它不是完整教学产品。
2. 跑通目标 → 计划 → 课时 → 练习 → 反馈 → 进度的完整旅程。
3. 接知识来源、动态供题、审核与完整题包要求。
4. 补齐教材 RAG/版本维护与更新通知、对话内学习工件、复习/主动教学和更多执行类型，按第四阶段能力清单验收。

允许不依赖模型的切片先行：目前已做来源版本/准入和固定间隔复习，不代表第 3、4 步整体完成。来源摘录由学习者提供，明确确认使用并设有效期；不冒充已抓取、语义验证或独立认证来源。复习自评不产生评分、Gate 或独立掌握度。

动态规划返回有序节点和来源版本，追加不可变草案，学习者明确确认当前精确版本后才激活。生成新草案不静默替换旧路线。节点正文只从当前确认版本和精确准入来源生成；没有来源的规划节点暂不能生成保存的课时。示例代码仅展示，回想问题不计分，不因正文生成或阅读更新进度。

动态题包保留每目标 2 练习/2 考核/1 补救、public-only 盲解、六审和受控发布。当前支持节点概念单选与 Python 整数数组输入/整数输出程序；后者五份盲解程序必须经过隔离运行验证。Gate 在核验实际已见内容、课时/对话与先修后明确开两题，一次锁定两份答案/程序；合格结果分别记概念或执行证据。模型报告不是客观认证，站外帮助不可观测，不以换 key 重考。任意程序、跨语言和完整跨题型关系仍逐项验收。

补救与普通练习不计独立掌握。概念和 Python 代码补救失败分别从同类型、同节点/版本/来源、未见且完整审核发布的练习中选精确后继；代码候选还须通过五份盲解执行资格。缺题时明确建立一条持久供给任务，新自动链审完合格后由服务端发布，旧手动入口保留；不伪造、不原题重试。代码一次锁定后经原 Runner/服务端评分，通过也只解除补救阻断，原失败保留，独立 Gate 仍须重新审核实际曝光。新课时/讲评进入实际上下文，使旧关系许可失效。

锁定回执可明确启动唯一 Tutor 讲评，不抢占活动用户问题，不改分、不自动开放后继。该切片不是自动教学推送。直接答案/H1–H3、完整 mastery/FSRS、主动教学与更多语言仍待做。质量失败可把精确报告/上下文交给新作者版本，重新盲解、六审和发布；同材料不刷审，旧失败与修订谱系不重置。

验收看真实用户结果、正确业务条件和实际持久化，不以目录、接口或测试数量替代。

## 第四阶段已确认的产品规则

- 材料接入、OCR/解析、切分、检查、修复、索引和合格发布由系统自动循环，用户不承担材料工程审批或手动重试。
- 千问系列作为 OCR、向量和重排序的优先候选，实际组合经真实材料验证。2026-11-02 用户允许其私有材料发送千问处理，允许使用已有账号开展三通道付费开发/验收，无地域和费用上限；不重复索取同项许可，不自动充值、升级或开通新收费服务，不替其他用户同意。
- 所有模型 API 凭据由用户自行配置；连接、非秘密模型 Profile/职责映射与秘密存储分离，按用户隔离并支持测试、轮换与撤销。当前环境变量配置不是此功能已经交付，不默认共享开发密钥。
- 多语言执行基座可先于完整课程适配，分别验收，不把注册项或编译成功当课程完成；SQL 首批按 MySQL/PostgreSQL/SQLite 独立方言设计，Rust/C++ 先评估编译环境，不自动追加完整课程承诺。项目内置支持规则/可信配方，不在安装包中一次捆绑全部工具链；用户学到相应语言时按需自动准备专用环境。
- 首次检测并引导准备本机隔离引擎；正式产品由应用管理本机后台组件，不要求学习者手工启动开发服务。引擎安装涉及的系统权限单独明确确认，不借路线授权运行任意提权命令。
- 基础语言及锁定工具链依赖按学习需要自动准备。制定完整路线时汇总环境需求，确认路线的按钮气泡一次询问额外课程依赖/框架；用户可同时同意安装或仅确认路线。默认只显示必要环境、用途和系统管理的隔离位置，版本/完整依赖、来源、资源及权限折叠展示。授权绑定路线与依赖/版本策略；同范围重建复用，不反复询问，超范围新增依赖或权限再确认。未同意可保留路线、先读教材或稍后准备，不自动删减目标或记实操通过。
- 实际依赖只进入本机专用隔离环境，不修改全局 SDK；安装同意不代替安全、兼容和评分资格。学习代码默认不联网，依赖下载仅走已授权出口，临时工作区与可复用环境分开；不执行任意联网仓库。
- 本机执行不等于完全离线：Tutor、OCR、向量及排序可按用户自配模型通道发送必要且获准的上下文；这不构成远程代码执行，不默认外发完整项目。
- 来源到期复核不等于全链路重做。元数据/措辞/实质变化/权限变化分级，复用未变结果，只重验实际受影响范围。
- 教材绑定覆盖完整学习周期；检查/适用性复核日期不自动使内容失效。没有真实截止要求时不人为制造短期使用权限到期。
- 系统准备新版并通知差异、影响与迁移代价，由用户决定更新、稍后或本轮保留旧版；未选择不自动切换，不因未读通知停课。实际撤权或执行安全故障独立处理。
- 学习工件承载内容、状态、操作和反馈，嵌在 Tutor 对话中；右侧只做文档/来源阅读，评分与进度仍归原业务所有者。
- 本轮只建立设计文档，五个交付包未因规格写成而成为已实现功能。
