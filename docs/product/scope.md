# Leornian 产品范围

## 产品目标

面向编程学习者，把学习目标、计划、课时、Tutor 对话、代码练习、反馈、进度与复习组织成完整学习体验。

这是整个项目的重新设计，不是仅修复旧 Aearn 的某条题库链路。分阶段实现不等于缩减最终产品目标。

当前已交付本地身份、目标、原生 Tutor、动态路线版本/确认与节点正文接线、固定 Python 评测闭环、来源摘录管理和基础复习。不是正式账号系统。动态路线/正文目前只通过自有模拟传输与真实库集成，真实模型尚未配置；正文生成不能替代审核题包或正式评测。完整状态和运行方式见根目录 README。

## 目标能力

- 学习者身份、偏好与数据归属。
- 学习目标、版本化计划、课时阅读、学习进度与掌握度。
- Tutor 多轮教学、提示、教学工件与中断后的明确续行。
- 可信材料检索、来源引用、版本和当前有效性管理。
- 动态题目与题包供给、质量审核、修订和受控发布。
- 练习、作答、反馈、评测 Gate 与受限代码运行。
- 复习安排、主动教学，各类学习工件与语言执行能力。

更细的教学规则、语言矩阵、审核角色与题包条件，在对应切片中从旧产品要求逐项核对；不能默认降低要求，也不把旧内部实现当作必须复制的规格。

## 已确认范围

- 仓库和项目名称：Leornian。
- 独立新仓库、独立新库，暂不迁移旧学习记录和运行状态。
- 直接移除 Sidecar，采用唯一原生 Agent Runtime。
- 模块化后端与清晰公开接口，后台任务和隔离执行服务独立运行。
- 旧仓库、旧库与历史记录保持不变。

## 当前不包含

- 旧数据迁移、旧运行状态兼容或旧现场恢复。
- 任意操作宿主终端、完整代码仓库自动修改等通用编程 Agent 能力。
- 微服务全面拆分、通用工作流平台或全量事件溯源。
- 公开发布、生产部署、自动开通付费资源。

## 推进方式

1. 先实现通信与持久执行基础，明确它不是完整教学产品。
2. 跑通目标 → 计划 → 课时 → 练习 → 反馈 → 进度的完整旅程。
3. 接知识来源、动态供题、审核与完整题包要求。
4. 补齐复习、主动教学和更多工件、执行类型，并按能力清单验收。

允许不依赖模型的切片先行：目前已做来源版本/准入和固定间隔复习，不代表第 3、4 步整体完成。来源摘录由学习者提供，明确确认使用并设有效期；不冒充已抓取、语义验证或独立认证来源。复习自评不产生评分、Gate 或独立掌握度。

动态规划返回有序节点和来源版本，追加不可变草案，学习者明确确认当前精确版本后才激活。生成新草案不静默替换旧路线。节点正文只从当前确认版本和精确准入来源生成；没有来源的规划节点暂不能生成保存的课时。示例代码仅展示，回想问题不计分，不因正文生成或阅读更新进度。

后续动态题包保留每个目标 2 练习/2 考核/1 补救、单题确定性校验、独立 public-only 盲解、课程匹配/难度/技术正确性/歧义/安全/对抗六角色审核及受控发布。完整关系、测评独立性、曝光与正式 Gate 仍逐项实现和验收，不能因人工样例跑通而省略。

验收看真实用户结果、正确业务条件和实际持久化，不以目录、接口或测试数量替代。
